Phone settings survive a boot before unlock, Magisk 31.1, Pixel 6a (Android 17), release-signed 0.4.0, 2026-11-26

Found on the build before the fix (release 0.4.0 without it):
  the settings file (credential-protected storage) held the Lab test number and the other settings
  reboot: the bridge connected 6 s after sys.boot_completed, before the PIN was entered
  unlock, open Lab: the Test number field was empty and "Set the test number first." was shown;
  in the same process, typing a number and reopening Lab showed it
  => the store read the locked file as absent at boot and answered with defaults until the
     process ended; a write after such a boot would have stored those defaults

After the fix (settings in device-protected storage, the old file migrated once it is readable):
  23:05:58  sys.boot_completed; 23:06:07 connected (+8.7 s), before unlock
            before unlock: no settings file of the bridge's own yet, the old file unreadable
  unlock:   files/datastore/phone-settings.preferences_pb appeared in device-protected storage
            with the test number, the relay settings and the migration marker; the old
            credential-protected file is still there for a rollback
  Lab:      Test number shows the stored number
  typing "+998..." key by key into the emptied field keeps the leading "+"

Unit tests: PhoneSettingsStoreTest (locked start then unlock, a write before the migration, the
marker against the kept file, a fresh install), PhoneSettingsTest, LabViewModelTest.
